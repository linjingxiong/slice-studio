## 在另一台电脑继续

在 Windows 上安装 Git、64 位 Python 3.12 和 Chrome，然后打开 PowerShell。

```powershell
git clone https://github.com/linjingxiong/slice-studio.git
cd slice-studio
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe install_models.py
.venv\Scripts\python.exe studio.py
```

在同一台电脑打开 [工作台](http://127.0.0.1:8765)。模型安装脚本会下载约 42.6 MiB 权重并核对 SHA-256。macOS 和 Linux 的虚拟环境解释器路径是 `.venv/bin/python`。

开发用的 Git 仓库包含源代码、需求、测试脚本和数字化验证记录。浏览器里的工作项目需要在旧电脑通过「项目 → 下载项目文件」导出 `.slice`，再通过新电脑的「项目 → 打开项目文件」导入。该文件包含原图、素材坐标和蒙版，应使用自己的文件传输方式。复跑原样图测试时，将旧电脑的三张 `test-assets` 参考图复制到新仓库的同名目录。已有文件的核验信息见 [测试输入清单](records/2026-11-27-fixtures.txt)。

用 Codex 接续时，打开克隆后的目录，可从这条指令开始。

## 原始需求与实施决策

- 把 AI 生成的 UI 参考图、图标合集、游戏素材和插画转换为能直接用于工程的透明独立素材。先做完整 Web 版，结构兼容后续 Tauri 2。采用真实识别算法和真实图片验收。
- 素材仅在本机处理。Web 端使用原生 ES modules、Canvas 2D 和 IndexedDB。Python 通过回环 HTTP API 提供识别、分割和导出。后续可让 Tauri 管理同一个本地处理进程。
- 均匀背景的素材表优先采用 OpenCV 颜色分割，复杂选区支持 GrabCut，复杂背景或指定选区可调用本地 MobileSAM。原图、独立蒙版和导出分开存储，坐标始终按已应用 EXIF 方向的原图像素表示。
- 当前支持导入、自动提取、框选和套索、刷改蒙版、缩放平移、撤销重做、项目恢复、透明 PNG 和带坐标清单的 ZIP 导出。

相关入口为 [开发指令](../AGENTS.md)、[界面规范](03-UI-UX.md)、[验收计划](04-开发计划与验收.md)和 [技术选型与验证报告](05-技术选型与验证报告.md)。

## 用户反馈与已处理的问题

1. 用户指出复古素材中的蝴蝶、帆船卡片边缘发白，并要求单独查看素材。增加了单素材对话框，以右侧双击、属性按钮或右键菜单打开。对话框支持深色、浅色、棋盘格、缩放和直接下载，显示的就是本机服务生成的透明 PNG。
2. 用户随后用灯笼指出，先前处理仍在外轮廓和把手内侧留下明显白边。现实现将较大的透明镂空也纳入清理，按距边缘的位置渐变处理 RGB 和 Alpha，并对接近背景色的 JPEG 残点减弱覆盖。实测对比灯笼的两侧把手和外轮廓，并检查灯罩中央纹理。
3. 有背景色估计的素材现在默认开启「清理白边」，已有项目同样生效。用户可以按素材关闭，显式设置以 `edgeCleanup` 保存在项目及 `.slice` 文件内。单素材下载经测试与引擎生成的灯笼 PNG 像素一致。基于同一原图区分浅色细节和背景仍需要估算。
4. 首次上传使用公开仓库的 `main`。另外验证了干净克隆下没有随附样图、未装模型时，仍可导入本地文件并走颜色识别。工作台按本机实际存在的文件显示示例入口。

## 验证记录与后续边界

- 初始发布的 8 项引擎测试、Chrome 157 全流程和干净克隆检查通过。Chrome 测试覆盖导入、编辑、项目往返、真实导出和取消后的恢复。灯笼镂空与灯罩纹理有专门回归测试。
